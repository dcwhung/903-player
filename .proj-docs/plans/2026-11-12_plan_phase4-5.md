## L0：`packages/catalog` schema

1. Catalog document 加選填 `banner?: { standard: AssetRef; long: AssetRef }`（兩個都要；validator 拒絕只得一張）；`schemaVersion` 唔使升（選填欄位，舊 player 會忽略）
2. 共用常數（S-805）：`ASSET_DIMENSIONS`（disc 600×600、tile 1216×684、bannerStandard 1200×517、bannerLong 2000×400）+ `ASSET_MAX_BYTES` 由 api 搬入 `packages/catalog`；api / admin 改為 import
3. Scan 分類：`listing` 嘅 images 分出 `cdCover` / `coverPhoto`（固定檔名，唔分大細寫）；其他圖照列入 `covers` 但唔自動配對
4. Contrast 計算（WCAG relative luminance）同 theme 檢查配對放 `packages/catalog`（admin 用、publish validator 出警告用）
5. Test：schema / validator、常數、檔名分類、contrast 值（對住已知數字）

## L1：api 0.8.0

1. D1 存 banner（document 式，同其他內容一樣經 draft → publish）；`GET` / `PUT` banner；「還原預設」= 刪 banner
2. Publish：有 banner 就寫入 `catalog.json`；validator 檢查兩張都在；theme contrast 唔合格只出警告；theme 10 色等於 `NEUTRAL_THEME` 出「未設定配色」警告（唔阻；L1 實作，用 `packages/catalog` 現有 `NEUTRAL_THEME`）
3. 上載白名單加 banner 兩個尺寸（用 L0 嘅 `ASSET_DIMENSIONS`）
4. R2 原圖代讀：`GET /api/r2-source?key=…`
    - 要登入；`key` 一定要喺該劇最新掃描結果嘅 `cdCover` / `coverPhoto` 入面（唔收任意 key，防 path traversal）
    - 大小上限（例如 20 MB，命名常數）、只准圖片 MIME
5. Test：auth、key 白名單、大小上限、banner publish validator
