## 指定檢查點

### (1) 補撳唔會遮住「表永遠開唔到」— ✅ 成立

`for (attempt = 0; attempt < SHEET_OPEN_TAPS && !visible; …)`：兩次都 `isShown(..., { timeout: SHEET_OPEN_TIMEOUT_MS })` 失敗 → `visible = false` → `transform = '(冇表)'` → `log(false, …)` → `run.mjs` 嘅 `log` 將 `failures += 1` 兼印 `FAIL`；`openSheet` return false，caller（第 178 / 193 / 266 / 316 行）照舊 early return。所以「按鈕壞咗 / 表 render 唔到」仍然係 FAIL，只係由 5 s 變 10 s 先報。

### (2) 冇無限 loop — ✅

上限係常數 `SHEET_OPEN_TAPS = 2`，`attempt` 每圈 +1；每圈最多一次 tap + 一次有 timeout 嘅 `waitFor`。最壞情況 2 × 5 s。

### (3) 冇固定 sleep（S-529）— ✅

只用 `locator.waitFor({ state: 'visible', timeout })`（經 `isShown`），條件一到即刻返，冇 `waitForTimeout` / `setTimeout`。原本 inline 嘅 `5000` 亦抽咗常數。

### (4) check 數唔變 — ✅

無論補唔補撳，`openSheet` 都只係 call `log` 一次，所以 590 唔會變 591；補撳時訊息尾加「，撳咗 2 下」。

### (5) CUI-0013 — ✅

只改目標 test：`it(name, fn, TYPECHECK_TIMEOUT_MS)`，常數有註解講明原因（單獨 ~1.4 s、coverage 平行 7.5 s、vitest 預設 5 s，連埋 CUI-0013 / S-574）。實測單獨 1480 ms，同註解一致；20 s 有 ~2.7× 餘量，又唔會長到令真係 hang 嘅情況等好耐。同一個檔冇其他 test 用 `nodeProgramErrors` / `ts.createProgram`，唔使一齊改。test 內容逐字冇改，只係 prettier 重新縮排。

### 🟡 Warning

#### W-513 — 補撳會將「甩閂之後第一下 tap 被食」變成 PASS，跳過咗 ticket 嘅「先確認原因」

- 位置：`e2e/arcSheet.mjs` `openSheet()`
- 描述：CUI-0010 嘅解決方案建議第一步係「先確認原因：失敗時截圖 + 記低 tap 前後 `#root` 有冇閂緊嘅 backdrop / `data-closing`」，之後先講補撳。今次直接補撳，原因仍然係推測。如果原因其實係 app 自己（例如閂緊嘅 backdrop / 手勢 handler 喺甩完之後仲攔住一下 tap），而將來有改動令佢由「偶然」變「次次」，e2e 會次次撳兩下、次次 PASS，只喺 PASS 行尾多咗「撳咗 2 下」，冇人會睇到。
- 影響：e2e gate 失去偵測一類現實 UI regression（甩閂後第一下撳唔到）嘅能力。真用戶通常唔會喺表剛剛消失嗰幾 ms 就撳，所以目前影響細；但呢個正正係 ticket 想先排除嘅可能。
- 方案 A：第一次撳唔到時記低診斷（`console.log('INFO …')`：tap 前後 `#root` 有冇 backdrop / `data-closing`、或者 `page.screenshot` 去 e2e 輸出目錄），而 `run.mjs` 最尾印「openSheet 補撳 N 次」總結。優：唔影響 check 數同 PASS 判斷，但次次補撳會好顯眼，亦順手完成 ticket 第一步。劣：多少少輸出 / 一個 module-level counter。
- 方案 B：補撳只限上一步係甩閂（`checkFling` 之後）嘅情況，其他地方第一下撳唔到照 FAIL。優：遮蓋範圍最細。劣：要將「上一步係乜」傳入 `openSheet`；而真係次次都中嘅話，甩閂後嗰個 case 仍然被遮。
- 推薦：A；ticket 驗證方式（連跑 5 次 590）完成時順手睇下總結有冇補撳，有就喺 ticket 記低原因。

### 🟢 Suggestion

#### S-625 — 第二下 tap 理論上可能撞正遲咗出現嘅表

- 位置：`e2e/arcSheet.mjs` `openSheet()` loop
- 描述：第一下其實有效但表 5 s 後先 mount：`isShown` timeout 之後、`count()` 之前表未入 DOM → 再撳；如果表啱啱喺之後出現，第二下可能落喺 backdrop 而閂咗佢。要 render 慢過 5 s 先會中，屬理論排列，唔影響今次判斷。
- 方案 A：維持現狀（5 s 已經好寬）。方案 B：第二下之前再 `isShown(sheetOf(p), { state: 'attached', timeout: SHORT })` 確認真係冇表。推薦：A，喺註解寫一句前提就夠。
