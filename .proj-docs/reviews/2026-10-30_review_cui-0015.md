#### W-515 — 填滿格嘅欄 × 行慢一拍：過場影到嘅新畫面用舊 / fallback 形狀，動畫中途跳

- 位置：`src/hooks/useElementSize.ts`（`useEffect` + `ResizeObserver`）；`src/components/HomeLandscapeGrid/useFillShape.ts`；`src/utils/viewTransition.ts`（`flushSync(update)`）
- 描述：`withViewTransition` 靠 `flushSync` 令新畫面喺 callback 入面 render 完，瀏覽器先影新畫面。但 `HomeFillGrid` 嘅大細係 ResizeObserver callback 先 `setSize`，呢個 update 唔係 sync，要 `flushSync` 之後先 render：
    - `close` / `open`：nav 由 64% 變全闊（或者相反），`flushSync` render 出嚟嘅仲係舊闊度揀嘅欄 × 行（例：1012 × 562 廣播劇 split 2 × 3 → full 應該 3 × 2），新畫面影咗錯嘅格，過場開始後 React 再 render 正確形狀，live 嘅 `::view-transition-new` 內容喺動畫中途變形 / 跳位。
    - `back`（內頁返主頁）：`HomeFillGrid` 新 mount，`size` 係 `UNMEASURED` → `fallbackShape`（√n 方格），新畫面就係 fallback，tile morph 去錯位，之後先跳返正確形狀。
    - 冇過場時（每次去闊橫版主頁、換 tab 因為 `key={tab}` 重新 mount）都有一 frame fallback 閃。
- 影響：用戶批咗嘅「格仔移位伸縮」過場（motion.html）喺真機有機會唔順 / 跳；jsdom test 睇唔到（冇 RO）。需要實機（Chrome / Safari 18）確認，但機制上一定慢一拍。
- 方案 A：喺 commit 時同步量：`useLayoutEffect`（冇 deps，每次 commit 都量，值一樣就唔 `setSize`）+ ResizeObserver 處理外部轉大細。`flushSync` 入面 layout effect 讀 `clientWidth` 會 force layout 拎到新闊度，`setSize` 喺 layout effect 入面係 sync re-render，`flushSync` 返嚟之前已經係正確形狀；mount 時都唔會閃 fallback。優：改一個 hook，所有用家受惠。劣：每次 commit 讀一次 layout（只限 `HomeFillGrid`，成本細）。
- 方案 B：RO callback 入面用 `flushSync(() => setSize(...))`，再喺 `HomeFillGrid` 第一次 render 前用 `useLayoutEffect` 量一次。優：改動更少。劣：`close` / `open` 時 RO 喺 rendering steps 先到，同 view transition 影新畫面嘅次序要靠瀏覽器實作，唔保證。
- 推薦：A（加 test：stub `ResizeObserver` + `clientWidth`，改 layout 之後同一個 `act` 內形狀已經更新）。

```ts
// 建議：useElementSize（節錄）
export const useElementSize = (ref: RefObject<HTMLElement | null>): ElementSize => {
    const [size, setSize] = useState(UNMEASURED);
    const measure = useCallback(() => {
        const el = ref.current;
        if (!el) return;
        const next = { width: el.clientWidth, height: el.clientHeight, uiScale: readUiScale(el) };
        // 一樣就唔 set，避免 layout effect 無限 render
        setSize((prev) => (sameSize(prev, next) ? prev : next));
    }, [ref]);
    // 每次 commit 同步量：flushSync（View Transitions）入面已經係新尺寸，mount 唔會閃 fallback
    useLayoutEffect(measure);
    useEffect(() => {
        const el = ref.current;
        if (!el || typeof ResizeObserver === 'undefined') return;
        const observer = new ResizeObserver(measure);
        observer.observe(el);
        return () => observer.disconnect();
    }, [ref, measure]);
    return size;
};
```

#### S-631 — `withViewTransition`：update throw 變 unhandled rejection；過場未開始前可以連撳

- 位置：`src/utils/viewTransition.ts`
- 描述：`void transition.finished.finally(...)` 喺 `finished` reject（update throw）時會再拋；`updateCallbackDone` 冇處理。update callback 要等下一 frame 先行，期間連撳 ⤢ 會 `navigate` 兩次（history 多一個重複 entry）；同 kind 連續兩次，第一個 `finished` 會清走第二個仲用緊嘅標記。
