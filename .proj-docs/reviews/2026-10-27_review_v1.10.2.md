## 範圍外嘅 `--shadow-mini-player`：判斷

- **原因成立**：已有嘅 `miniPlayerShadow.node.test.ts` 鎖住「陰影向下長度（y + blur）< 卡底間距」，防止 iOS viewport 底邊切出一條深色縫，而呢條規則係之前用戶睇過嘅問題。間距縮到 8px 之後，如果照用 `--shadow-floating`（2 + 10 = 12），就會違反呢個不變式。新值 `0 2px 5px` 計出嚟係 2 + 5 = 7，細過 8。
- **做法啱**：開一個新 token 俾 mini player 專用，`--shadow-floating` 個值冇變，ArcSheet 唔受影響；註解亦寫清楚點解要分開。
- **不足**：mini player 陰影會明顯變淺、變短，呢個係可見嘅視覺改動，但唔喺用戶批准嘅範圍（spacing）入面。見 S-500。

#### S-499 — 第二隻手指撳落會覆蓋緊進行中嘅捽 session

- 位置：`src/components/DramaShelf/useShelfFocus.ts` 嘅 `useShelfScrub` → `onPointerDown`
- 描述：只要有 pointerdown，`sessionRef` 就會被換成新嘅 session，連 `isPrimary === false`（第二隻手指）都一樣。結果係第一隻手指捽到一半，第二隻手指輕輕掂一下，捽就會靜靜雞停咗；第一隻手指之後嘅 move / up 因為 `pointerId` 唔對而被略過。
- 影響：好少見。`pressRef` 會由第二隻手指嘅 click 或者 pointercancel 清走，所以唔會卡住；只係手勢中途斷咗。
- 方案 A：喺 `onPointerDown` 加 `if (!event.isPrimary || sessionRef.current) return;`，有 session 就唔換
    - Trade-off：一行，最貼合「一隻手指捽」嘅意圖
- 方案 B：只係唔理 `!isPrimary`
    - Trade-off：更簡單，但滑鼠 + 觸控同時用嘅情況未完全處理
- 推薦：A

#### S-500 — 收窄 mini player 陰影係範圍外嘅視覺改動，要用戶確認

- 位置：`src/styles/tokens.css` 嘅 `--shadow-mini-player`、`MiniPlayer.module.css` 嘅 `.player`
- 描述：改法本身合理，見上面嘅判斷。但陰影由 10px blur 改到 5px，係用戶睇得出嘅變化，而 Design Origin 只係寫 behaviour / spacing。
- 方案 A：main agent 喺 PR description 寫明，並且照 UI Visual Confirmation Gate 請用戶喺 iPhone 睇一次
    - Trade-off：多一步確認
- 方案 B：唔改陰影，改為將 `MIN_CARD_GAP_PX` 嘅檢查限定喺 viewport gap > 0 嘅情況
    - Trade-off：會削弱一條防止深色縫嘅不變式，唔建議
- 推薦：A

#### S-501 — `useTileProps` 已經唔係 hook，但仲用緊 `use` 前綴

- 位置：`useShelfFocus.ts` 嘅 `useTileProps`
- 描述：改咗之後佢只係一個 curried function，入面冇 hook，因為 `pressRef` 由外面傳入。`use` 前綴會令人以為要跟 Rules of Hooks，而且 lint 唔會再幫手檢查佢。
- 方案 A：改名做 `tilePropsFor(focus, focusTile, pressRef)`
- 方案 B：將 `pressRef` 嘅 `useRef` 搬返入 `useTileProps`，再經 return 交俾 `useShelfScrub`
- 推薦：A（改動最細）

#### S-502 — 捽手勢嘅 cancel / 多隻手指 / capture 冇測試

- 位置：`src/components/DramaShelf/DramaShelf.test.tsx`
- 描述：已經有 6 個整合測試覆蓋主要行為。但係有幾樣冇測：
    - 捽到一半收到 `pointercancel`：focus 應該保留，下一下撳要正常
    - 郁過 slop 之後應該有 `setPointerCapture`（可以 stub `HTMLElement.prototype.setPointerCapture`，再斷言有冇被叫）
    - 唔同 `pointerId` 嘅 events 唔理
- 方案 A：加 2–3 個 case（同 S-499 一齊做）
- 方案 B：只加 `pointercancel` 嗰個 case
- 推薦：A
