### 🟢 Suggestion

#### S-640 — `stop()` 靠 `pause` event 先停 stall watchdog；element 已 paused 時 watchdog 會喺 ✕ 之後重試 `play()`，張卡同聲都會返嚟

- 位置：`src/player/AudioController.ts` `stop()`；經 `useOnPlayStart`（`useRestoreMiniPlayerOnPlay`、`useReopenHomePlayerCardOnPlay`）
- 描述 / 證據：見 (5) 候選 1。用戶撳 ✕（或者直版左滑關閉）係明確「唔想再播」，但係 watchdog 嘅 deadline 仍然排住，到期 `retryStalled()` → `reload` + `play()`。
- 影響：最壞情況閂完張卡之後幾秒自己再出聲，張卡 / mini player 彈返出嚟，最多持續到 watchdog 用完次數 / 30 秒上限。觸發條件（element 已 paused 而 watchdog 仲睇住）未證實喺實機出現。
- 方案 A：`stop()` 直接 `this.stopWatchingStall()`（同 `onStopped` 一樣清 `playIntent`、`isPlaying`），唔靠 event。優：一行，任何情況都停得切。劣：要同 `onStopped` 嘅 `frozenBeforeStop` 邏輯對齊（stop 唔需要記 frozen）。
- 方案 B：`FakeAudio.pause` 改成 spec 行為（已 paused 唔發 event），睇下仲有冇其他路徑依賴呢個 event。優：test 更似真。劣：可能影響好多現有 test。
- 推薦：A，加 test（spec 行為嘅 pause + watchdog 睇住 → `stop()` → 推過 `STALL_MAX_WAIT_MS` 冇 `play()`）；B 可以之後另做。同時睇返 21/09 嗰次嘅 playback log 有冇 ✕ 之後嘅 `retry`。

#### S-641 — `withViewTransition`：`startViewTransition` 同步 throw 會令 `pending` 永遠係 true

- 位置：`src/utils/viewTransition.ts`
- 描述：`pending = true` 之後先叫 `document.startViewTransition(...)`；如果佢 throw，冇地方清 `pending`，之後所有過場（✕、把手、⤢、返主頁）都直接 `return`，連 update 都唔行，即係掣冇反應。
- 方案 A：`try { … } catch { pending = false; update(); }`（throw 就當唔支援，直接更新）。方案 B：加安全網，超過一段時間（例如 1 秒）update 都未行就清 `pending`。推薦：A + test（stub `startViewTransition` throw → update 照行，下一次照開到過場）。

#### S-642 — 閂咗之後由內頁返主頁，成頁會縮入把手

- 位置：`HomePlayerHandle.tsx`（`player-panel`）× `global.css` `html[data-view-transition] main[data-player-page]`
- 描述：✕ 之後嗰集停喺暫停（`useAudioBusy` 當 busy），撳格仔入節目頁唔會自動播，所以張卡保持閂咗。喺節目頁撳返主頁（`back` 過場）：舊畫面嘅內頁 `main` 同新畫面嘅把手同名，成頁會 morph 縮入 26px 闊嘅把手。唔係壞，但唔係用戶喺 motion.html 揀過嘅效果（批咗嘅係「卡 ↔ 內頁」同「卡 ↔ 把手」）。
- 方案 A：把手只喺 `close` / `open` 期間有名（同內頁 `main` 一樣用 `html[data-view-transition='close' | 'open']` CSS 加名）；`back` 時內頁成頁淡出。方案 B：保留，請用戶喺實機睇過確認。推薦：A（改動細，同 S-634 嘅做法一致）。

#### S-643 — `pause()`（鎖屏 / 耳機嘅暫停）都係靠 `pause` event 先停 watchdog

- 位置：`src/player/AudioController.ts` `pause()`；經 `useMediaSession` 嘅 pause action
- 描述：同 S-640 一樣嘅漏洞：媒體控制嘅 pause 唔理 element 係咪已經 paused 都會叫 `controller.pause()`；如果 element 已經 paused 而 watchdog 仲睇住，冇 `pause` event，watchdog 之後會重試 `play()`，用戶暫停咗又再出聲。觸發條件同 S-640 一樣未證實喺實機出現。
- 方案 A：`pause()` 同 `stop()` 一樣直接 `stopWatchingStall()`；但要保留 `onStopped` 嘅 `frozenBeforeStop`（鎖屏暫停 → Play 要即刻 reload，v1.20.9），即係先計 `frozen = this.isStuck()` 再停 watchdog。方案 B：只喺 `this.audio.paused` 已經 true 時自己行 `onStopped()`（模擬冇發嘅 event）。推薦：B（唔改正常路徑，只補冇 event 嘅情況），加一個同 S-640 一樣嘅 test。
