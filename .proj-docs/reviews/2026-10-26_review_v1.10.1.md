#### W-463 — Debug panel 寫死咗 font-family

- 位置：`src/components/ViewportDebug/ViewportDebug.module.css:12`
- 描述：`font-family: ui-monospace, monospace;` 係寫死嘅字型 string。`sw-coding-style-css` §1 / §6 規定 font-family 一定要 declare 做 CSS variable，reviewer 要逐個 flag
- 影響：唔影響用戶，因為係隱藏 panel。但係開咗個先例，以後會有更多 component 自己寫字型 stack
- 方案 A：喺 `tokens.css` 加 `--font-family-mono: ui-monospace, monospace;`，panel 改用 `var(--font-family-mono)`
    - Trade-off：多一個 token；不過以後其他 debug / code 顯示都可以共用
- 方案 B：直接用 `var(--font-family)`，唔用等寬字型
    - Trade-off：零新 token，但數字唔對齊，對數時冇咁易睇
- 推薦：A

#### W-464 — 疊卡書架由「唔使捲」轉去「要捲」時，focus 同 snap 位對唔上；模式轉換冇測試

- 位置：`src/components/DramaShelf/useShelfFocus.ts:64-74`（`useShelfLayout`）
- 描述：喺唔使捲嘅模式，撳暗咗嘅卡只會 `setFocus(index)`，唔會捲（`scrollTop` 一直係 0）。之後如果書架變矮，轉咗去要捲嘅模式，例如 recordings 載入完、mini player 出現令書架縮短：`focus` 會停喺舊 index（例如 2），但 `scrollTop` 仲係 0，snap 位上面其實係第 1 張。咁就違反咗 T2「停喺 snap 位嗰張係 focus」嘅不變式，要等用戶捲一下，`onScroll` 先會修正返。另外，反方向（要捲 → 唔使捲）會 `scrollTop = 0`，呢個係 dev note 要求驗證嘅行為，但冇任何測試斷言佢
- 影響：純粹視覺上唔一致，會自己修正返，唔會開錯劇。但係呢個係 T2 嘅核心互動規則，而且兩個轉換方向都冇測試保護
- 方案 A：喺 `update()` 入面比較上一次嘅 `scrolls`。由 false 變 true 時，`shelf.scrollTo({ top: snapTop(focus, next) })`，即係捲去而家 focus 嗰張；再加兩個測試（650 → 400 同 400 → 650），用 `ResizeObserver` stub 觸發
    - Trade-off：`update` 要攞到最新嘅 `focus`（用 ref），多幾行
- 方案 B：由 false 變 true 時 `setFocus(0)`，即係 reset 返第一張
    - Trade-off：簡單，但用戶揀咗嘅 focus 會冇咗
- 推薦：A（保留用戶揀咗嘅卡）。最少都要補返兩個轉換方向嘅測試

- 方案 B：拆成兩個測試（冇 mini player / 有 mini player）

#### S-495 — `fillRows` 喺極矮嘅高度會計出負數行高

- 位置：`src/components/ShowGrid/showGridPages.ts` 嘅 `fillRows`
- 描述：當 `availablePx < dotsPx`（例如鍵盤彈出，或者極細嘅 split view），`roomPx` 會變負數，結果係 `repeat(1, -Npx)`。呢個值係 invalid CSS，瀏覽器會忽略，所以實際效果係退返 16:9，唔會爆，但語意唔清楚
- 方案 A：`rowPx: Math.max(0, Math.min(sharedPx, tilePx * maxGrow))`，再加一個 case 測試
- 方案 B：`sharedPx <= 0` 時返回 `{ rows }`（唔填滿）
- 推薦：B（同「未量到」嘅 fallback 一致）

#### S-496 — `useShelfLayout` 每次 ResizeObserver callback 都 set 新 object

- 位置：`useShelfFocus.ts:70`
- 描述：ShowGrid 有 `sameLayout` 擋住重複 set，書架就冇。每次 RO callback 都會 re-render（例如 iOS 工具列伸縮時連續觸發），加上改 inline padding 會再觸發多一次
- 方案 A：加 `sameShelfLayout`（比較 `stepPx` / `cardPx` / `scrolls` / `tailPx`），喺 `setLayout(prev => same ? prev : next)` 用
- 方案 B：觀察 `border-box`（`observer.observe(shelf, { box: 'border-box' })`），咁改 padding 就唔會觸發
- 推薦：A + B 一齊做

### W-464 — `src/components/DramaShelf/useShelfFocus.ts`

```ts
const sameShelfLayout = (a?: ShelfLayout, b?: ShelfLayout): boolean =>
    a?.stepPx === b?.stepPx &&
    a?.cardPx === b?.cardPx &&
    a?.scrolls === b?.scrolls &&
    a?.tailPx === b?.tailPx;

const useShelfLayout = (
    shelfRef: RefObject<HTMLElement | null>,
    count: number,
    enabled: boolean,
    focusRef: RefObject<number>, // W-464：最新嘅 focus，轉去要捲時捲返去佢度
) => {
    const [layout, setLayout] = useState<ShelfLayout>();
    useLayoutEffect(() => {
        const shelf = shelfRef.current;
        if (!enabled || !shelf) return;
        let scrolled: boolean | undefined;
        const update = () => {
            const next = measure(shelf, count);
            if (next && !next.scrolls) shelf.scrollTop = 0;
            // W-464：由唔使捲變要捲，snap 位要對返 focus 嗰張（T2 不變式）
            if (next?.scrolls && scrolled === false) {
                shelf.scrollTop = snapTop(focusRef.current, next);
            }
            scrolled = next?.scrolls;
            // S-496：一樣就唔 re-render
            setLayout((prev) => (sameShelfLayout(prev, next) ? prev : next));
        };
        update();
        const observer = typeof ResizeObserver === 'undefined' ? null : new ResizeObserver(update);
        // S-496：border-box，改 inline padding-bottom 唔會再觸發
        observer?.observe(shelf, { box: 'border-box' });
        return () => observer?.disconnect();
    }, [shelfRef, count, enabled, focusRef]);
    return enabled ? layout : undefined;
};
```

（`useShelfFocus` 入面加 `const focusRef = useRef(focus); focusRef.current = focus;`，再傳入去。）

### 🟢 S-498 — `onScroll` 每個 scroll event 都行一次完整 `measure`（developer 自己 flag 咗）

- 位置：`src/components/DramaShelf/useShelfFocus.ts:129`（`scrollFocus`）
- 描述：每次 scroll 都會 `getComputedStyle`、讀 6 個 token 同 4 個 padding、讀 `clientHeight` / `clientWidth`，再行一次 `stackLayout`。
    - 捲動本身唔會令 style / layout 變 dirty，大部分 frame 只係讀 cache，成本好低。
    - 但係 `setFocus` 換咗 `data-focused` 之後，下一個 scroll event 嘅 `getComputedStyle` 會即刻做一次 style recalc。因為只係 transform / filter，唔使重做 layout，所以影響細。
    - scroll event 每個 frame 最多一次，實際上唔會造成可見嘅卡頓；不過書架係 snap 捲動，低階 Android 可以留意下。
- 方案 A：先做平嘅檢查。喺 layout 入面記低量度時嘅 `clientHeight` / `clientWidth`，`scrollFocus` 先比較呢兩個數，唔同先當係轉換中而略過，唔使 `getComputedStyle`
    - Trade-off：多兩個欄位；token 喺 runtime 改咗（例如 `--ui-scale`）唔會發覺，不過嗰種情況 RO 都會觸發
- 方案 B：保持現狀，喺註解寫明成本，並且用 Performance panel 喺低階機確認冇 long task
    - Trade-off：零改動
- 推薦：A（改動細，又保持正確性）；唔做都唔阻 release
