### 3.2 開發者嘅「冇檔集數 → 關閉播放器撳唔到約 30 s」

做法：1180×820 張卡清單撳「21/09」行（route 做 404 / 永遠唔答 / 20 s 後先 404），之後撳「關閉播放器」，量 click → `fillWithHandle` 時間，再睇 35–45 s 入面有冇再出卡 / 再播；觸控版再每秒 `elementFromPoint` 睇個掣有冇畀嘢擋住。

| Build                 | 情境                                                                      | 結果                                            |
| --------------------- | ------------------------------------------------------------------------- | ----------------------------------------------- |
| `006e121`（修之前）   | 404 / abort / hang × 撳完等 0、0.3、1.5、4.5、9、14 s 先撳關閉            | ✅ 13 次全部 23–87 ms click、79–211 ms 收埋     |
| `006e121`             | 觸控 1012×562 / 1180×820 × 404 / hang，等 35 s 期間個掣冇畀嘢擋           | ✅ 4 / 4，tap 後 51–123 ms 收埋                 |
| `006e121`             | 404 / hang / 20 s 慢 404 × 之前播緊 / 冇播，關閉後睇 45 s                 | ✅ 6 / 6 一直 `fillWithHandle/paused`，冇再出卡 |
| `006e121` / `e4897d5` | 播緊 → 外部 `pause()`（模擬鎖屏 / 耳機暫停，S-643）→ 關閉，睇 36 s        | ✅ 兩個 build 都冇再出卡、關閉後 `play()` 0 次  |
| **`e4897d5`**         | 404 / hang × 之前播緊 / 冇播，關閉後睇 41.5 s，數 `HTMLMediaElement.play` | ✅ 4 / 4：冇再出卡、冇再播、**`play()` 0 次**   |

結論：Chromium 重現唔到「30 s 撳唔到」，修之前都冇。Reviewer 嘅 S-640 機制（element 已經 paused 時 `pause()` 冇 event，watchdog 照重試 `play()` → `useOnPlayStart` 開返張卡、再出聲，最多 `STALL_MAX_WAIT_MS` 30 s）同 S-643 都係 iOS Safari 先容易撞到嘅時序（Chromium 嘅 404 / 卡住唔會令 element 喺 watchdog 仲睇住時變 paused）。修正（S-640、S-643）喺 `AudioController.test.ts` 用 spec 準確嘅 `FakeAudio.pause` 鎖住；呢度證實修正冇令關閉之後有任何 `play()`。**冇開 CUI-0017**：重現唔到，而且最可能嘅原因已經修咗；要實機驗（見建議 2）。
