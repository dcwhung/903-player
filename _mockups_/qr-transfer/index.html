⑤ 實作建議（純文字）

壓縮格式（建議 v1）

  1. 只放 id，唔放 URL：進度 key 而家係音檔 URL（約 120–200 字），匯出時轉做短 ref，匯入時用 catalog 砌返 URL（episodes.ts 同節目錄音嘅砌法）：
    • 節目：s<節目 index>.<日數>（日數 = 2020-01-01 起計；開咪時間唔同 fileTime 先加 .HHMM）
    • 短篇劇：r<劇 index>.<短篇 index>.<集數>
    • 每日劇：y<劇 index>.<日數>（重播加 .r）
  2. 節目 / 劇 id 用 payload 入面嘅字典（s / d 陣列），唔靠 catalog 次序；短篇 index 就要 drama.json 嘅 arcs 只可以加喺尾（或者改用短篇名，大約每集多 6–9 byte）
  3. JSON 陣列短 key：{"v":1,"t":匯出分鐘,"s":[…],"d":[…],"p":[[ref,幾耐前(分鐘),長度(秒),位置(秒，-1 = 聽完)]…],"b":[[ref,幾耐前]…]}；時間全部用「匯出前幾多分鐘」，數字細、deflate 食得落
  4. TextEncoder → CompressionStream('deflate-raw') → base64url（冇 =）；Safari 16.4+ / Chrome 103+ / Firefox 113+ 先有 deflate-raw，冇就唔出搬機掣
  5. 連結：https://…/903-player/#import=1.<base64url>；版本號 1. 放喺壓縮外面，未解壓已經知道識唔識讀；新版讀舊版 OK，舊版見到 2. 就話「連結唔啱用，請先更新 app」
  6. 過期：t 超過 7 日當過期（建議值，見問題）；合併用 updatedAt 比較，舊連結其實唔危險，但「覆蓋」就會倒退
  7. 壞連結（base64 / 解壓 / JSON / schema 驗證任何一步失敗）一律「連結唔啱用」，唔寫任何嘢入 storage
