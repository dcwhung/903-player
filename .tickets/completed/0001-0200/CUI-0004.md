## 問題描述

v1.10.2 新增嘅書架捽 focus（`useShelfScrub`，`4172d25`）註解寫明「手指 / pen（滑鼠撳住都得）上下捽」。手指同 pen 用得，但滑鼠唔得：喺劇集卡度撳住滑鼠向下拖，瀏覽器會開始 HTML5 拖放，因為卡入面嘅 `<img class="art">` 預設 `draggable = true`。拖放一開始就會發 `pointercancel`，`finish()` 收咗個 session，focus 冇郁到。

CSS 只加咗 `touch-action`，冇擋圖片拖放。同類手勢有先例：`ShowCardStack.module.css` 用咗 `-webkit-user-drag: none` 同 `user-select: none`。

另一個風險（Chromium 模擬唔到，要真機確認）：iOS Safari 長按圖片可能會出拖放預覽或者 callout。如果用家撳住停一陣先開始捽，可能會被打斷。

## 重現步驟

1. 390×844 直版，冇 mini player，廣播劇 tab（4 套劇，唔使捲模式），用滑鼠，唔係 touch
2. 喺卡 0 撳住滑鼠，向下拖到卡 2，放手

## 預期結果

focus 跟住變卡 2，唔會打開劇集，同手指捽一樣。

## 實際結果

focus 仲係卡 0。事件次序：`pointerdown → pointermove → dragstart → pointercancel`。

如果用 script 喺 `dragstart` 度 `preventDefault()`，focus 就會正確變做 2，證明係圖片拖放搞到。

## 環境

- **測試環境**：local `vite preview`，Chromium（預裝 playwright 1.63.0），滑鼠（冇 hasTouch）
- **相關版本**：`release/v1.10.2` @ `47db9e2`

## 影響範圍

- **受影響功能**：直版書架嘅捽 focus（滑鼠 / 觸控板）。手指同 pen 正常
- **受影響用戶**：用窄嘅直版桌面視窗、又用滑鼠拖嘅用家（好少）。真機長按嘅情況未確認

## 解決方案建議

- 方案 A（推薦）：`.shelf[data-stacked]` 入面嘅 `.art` 加 `-webkit-user-drag: none`，同 ShowCardStack 一樣；`<img>` 加 `draggable={false}`；需要嘅話加埋 `-webkit-touch-callout: none` 同 `user-select: none`
- 方案 B：喺書架 `onDragStart` 度 `preventDefault()`
- 測試：加一個 node CSS test 鎖住 user-drag，或者加一個 DOM test 驗證 `draggable` 係 false

## 驗證方式

QA script `scratchpad/e2erun/qa11/mouse.mjs`：用滑鼠撳住拖，0 → 2，唔會 navigate；之後撳 focus 卡會打開。另外喺 iPhone 真機試長按卡 0.5 秒再捽。
