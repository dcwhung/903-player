## 問題描述

v1.10.1 嘅直版節目格（T8「直版用盡高度」）會將每行拉高，最多到 16:9 × 1.3。不過頁頂橫額嘅高度仲係按 16:9 格高計（`src/components/HomeBanner/HomeBanner.module.css` 嘅 `.image`：`height: calc((100cqi - gap) / 2 × 9 / 16)`，註解寫住「高度 = 一格節目嘅高」）。

所以 repo 自帶 e2e（`e2e/run.mjs` 嘅 `checkHomeBanner`，第 97–118 行）入面「橫額高 = 節目格高（±1px）」嘅不變式唔再成立，`npm run e2e` 有 3 個 check 失敗。CI（`.github/workflows/deploy.yml`）只跑 lint + `npm test`，唔跑 e2e，所以 CI 捉唔到。Code review 都冇跑 e2e。

app 本身行為冇壞：T8 proposal 嘅 mockup 本身就係橫額唔郁、格拉高。問題係 e2e 同 HomeBanner 嘅註解仲停留喺舊規則，兩邊對唔上。

## 重現步驟

1. `npm run build`
2. 跑 `node e2e/run.mjs`（sandbox 要用 repo 外面嘅 runner，見 QA report「E2E 點樣跑」）
3. 睇 `主頁：橫額高 … = 節目格高 …` 嗰 3 行

## 預期結果

e2e 全綠，而且 e2e 斷言同 HomeBanner 註解都同 T8 嘅規則一致。

## 解決方案（完成後填寫）

328e8c2 `test(e2e): CUI-0001`（方案 A）：`e2e/run.mjs` 嘅 `checkBannerHeight` 改為「橫額高 = 一欄闊 × 16:9（±1px）」同「節目格高喺 [16:9, 16:9 × --show-tile-max-grow] 之內（±1px）」，token 由 `:root` 讀；`HomeBanner.module.css` 註解改為「最矮一格節目嘅高」。冇改 app 行為。

### 原本建議

- 方案 A（推薦）：當 T8 已經批准咗「橫額唔郁、格拉高」，改 e2e 嘅斷言。橫額高 = 2 欄 16:9 格高（±1px），節目格 h/w 喺 [9/16, 1.3 × 9/16] 之內。同時更新 `HomeBanner.module.css` 嘅註解。只改 test 同註解，唔使 bump version
- 方案 B：要橫額跟住格一齊拉高（例如用 ShowGrid 嘅 `rowPx` 做 CSS 變數）。呢個係可見嘅 UI 改動，要先問用戶、做 UI Visual Confirmation Gate
- 揀 A 定 B，要 main agent 同用戶確認，因為 T8 從來冇講過橫額要唔要跟格高
