## 問題描述

`e2e/touch.mjs` 嘅 `checkReducedMotion`（約第 466–492 行）斷言「捽碟四分一圈 seek ≈ 15s ±3s」。量法係「拖完之後 `aria-valuenow` − 拖之前」，但拖嗰陣音頻仲播緊：慢速 arc 每步 90ms，成個手勢要 1–2 秒以上。所以量到嘅數已經包埋播放前進咗嘅時間，結果經常喺 +17s（tolerance 上限 18s），機慢少少就會去到 +19s，然後 fail。

呢個係 test 時序問題，唔係 app bug：

- `touch.mjs` 同碟面 / seek code 喺 v1.10.1 冇改
- v1.10.0 嘅 QA run 都量到 +17s

## 重現步驟

1. `npm run build`
2. 連跑 `e2e/run.mjs` 幾次（sandbox 用 repo 外面嘅 runner）
3. 留意 `390×844 觸控減少動畫：捽碟唔跟手指轉（transform「」）但照樣 seek（+Ns）`

## 預期結果

每次都 PASS，seek 量度唔受播放時間影響。

## 實際結果

v1.10.1 re-verify 連跑 3 次：+17s PASS、+17s PASS、**+19s FAIL**（545/546）。

另外，正常動畫嗰個 check（`checkDiscScrub`）用同樣量法，量到通常係 +15s。即係減少動畫嗰次手勢期間播放走得多啲，貼住 tolerance 上限。
