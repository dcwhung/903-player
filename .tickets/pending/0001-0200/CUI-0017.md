## 問題描述

同一個 origin 開住兩個 tab（A、B），兩個都冇播嘢（冇揀錄音 → 規則係即刻換）。部署新版之後：

- 一個 tab 收到 `onNeedRefresh` → 發 `SKIP_WAITING` → reload 去新版 ✅
- 另一個 tab **從來冇收到 `onNeedRefresh`**，`controllerchange` 嚟嘅時候 `applied = false`、`pendingAction = undefined`，`handleControllerChange` 當係第一次安裝唔理 → **停喺舊版**；返前景、等 61 s、hidden → visible 都唔會換

Chromium（Playwright）swapped-build 實測（390×844，星期日）：

| 情境                                        | Build                    | 結果                                                                              |
| ------------------------------------------- | ------------------------ | --------------------------------------------------------------------------------- |
| A 第一次開（未 reload）+ B，B 叫 `update()` | v1.21.5 → v1.21.6        | 2 / 2：A 換咗、**B 停喺 v1.21.5**                                                 |
| A、B 都係返嚟用戶，B 叫 `update()`          | v1.21.5 → v1.21.6        | 4 / 4：B 換咗、**A 停喺 v1.21.5**（第 4 次再快轉 61 s + hidden → visible 都冇換） |
| A、B 都係返嚟用戶，A 叫 `update()`          | v1.21.5 → v1.21.6        | 3 / 3 得一個 tab 換（2 次 A 停、1 次 B 停）                                       |
| A、B 都係返嚟用戶，B 叫 `update()`          | v1.21.3（main）→ v1.21.5 | 1 / 2 A 停喺舊版（main 已經係咁）                                                 |

（A 播緊嘢 + B 換嘅情境 2 / 2 ✅：A 停播 + 61 s + 收埋就換，即係 S-647 修正有效；問題只喺「搶輸嘅 tab 未收到 onNeedRefresh」。）

## 根源分析

workbox-window 7.4（`build/workbox-window.prod.es5.mjs`）：

- 自己註冊嗰個 SW 嘅更新：`installed` 之後 `setTimeout(200)` 先 dispatch `waiting`，而且要 `registration.waiting === sw` 先 dispatch
- vite-plugin-pwa prompt 模式靠 `waiting`（或者 external 嘅 `installed`）先 call `onNeedRefresh`
- 另一個 tab 喺呢 200 ms 入面已經 `SKIP_WAITING`，SW 變 `activating`，`registration.waiting` 變 `null` → 呢個 tab 嘅 `waiting` 永遠唔 dispatch → `onNeedRefresh` 冇 call；plugin 嘅 `controlling` listener 都係喺 `showSkipWaitingPrompt` 入面先加，所以 `onNeedReload` 都冇
- 第一次開嘅 tab 行 external 路（`installed` 即刻 call `onNeedRefresh`，冇 200 ms），所以佢差唔多一定搶贏

## 解決方案建議

`handleControllerChange` 唔好淨係靠 `applied` / `pendingAction` 分「第一次安裝」定「換版」：

- 喺 `main.tsx` 記低頁面載入時 `navigator.serviceWorker.controller` 有冇值
- 載入時已經有 controller → 任何 `controllerchange` 都係換版
- 載入時冇 controller → 第一次 `controllerchange` 係 clientsClaim（唔理），之後嘅先係換版
- 係換版就 `handleNeedReload()`（已經會按播放 / grace / hidden 規則等，`reloadOnce` 防重複）

## 驗證方式

- Unit：`UpdateManager` 加「載入時有 controller、冇 onNeedRefresh、controllerchange → 冇錄音即刻 reload；播緊等停 + grace + 收埋先 reload」、「第一次開：第一下 controllerchange 唔 reload、第二下 reload」
- Swapped-build：兩個 tab（返嚟 / 第一次開 × 邊個叫 `update()`）× ≥ 3 次，兩個 tab 都要 reload 1 次去新版；A 播緊時唔可以 reload
